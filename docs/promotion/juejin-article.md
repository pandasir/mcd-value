## 三个每天都在发生的"多花钱"

以下数字不是举例编的，全部来自**同一家真实门店（深圳同方信息港）2026-10-14 的菜单快照**。跑 `demo.py` 就能复现。

### ① 同一批东西，换个买法少花 ¥12

你说想点「巨无霸 + 薯条 + 可乐」：

```
单点买法    巨无霸 ¥25.5 + 薯条 ¥13.5 + 可乐 ¥9.5 = ¥48.5
换个买法    「巨无霸三件套」× 1                    = ¥36.5
                                                   ─────────
你多花了                                         ¥12.0
```

在这家店，**12 组已验证的汉堡单点与对应三件套**全部便宜 ¥12.0——这个差价在这 12 组里相同。

### ② 你手里的券，其实在漏水

优惠券不是"手里的资源"，是**有保质期的钱**。麻烦在于券名里往往没有金额：「王牌小食拼」这张券值多少？菜单里根本没有这个商品。我拿券去计价接口逐一实测：

```
[顺手可用] 中薯条买一送一   值 ¥13.5 · 还剩 3 天
[顺手可用] 13.9浓浓黑巧      值 ¥ 7.1 · 还剩 6 天
[顺手可用] 王牌小食拼        值 ¥ 6.1 · 还剩 3 天
[不清楚]   6 张早餐券       券名推不出金额，我们就不猜

名义总额 ¥26.7 —— 看起来不错。
但按你的真实点单频率（8 笔订单、212 天、0.26 单/周）：

你能用掉的只有 ¥13.5，另外 ¥13.2 注定随券过期白扔。
```

**只算"券面总额"的助手，会告诉你"你有 ¥26.7 的券"；它告诉你的是"你只能用掉 ¥13.5"。** 只算前者是自欺。

### ③ 「份数更多反而更便宜」，有前提

这家店有 8 组"三件套比四件套还贵"的怪事：

```
培根安格斯厚牛堡   三件套 ¥45.5 > 四件套 ¥37.0 → 省 ¥8.5，还多一份
板烧鸡腿堡         三件套 ¥34.5 > 四件套 ¥28.0 → 省 ¥6.5
巨无霸             三件套 ¥36.5 > 四件套 ¥32.0 → 省 ¥4.5
```

看着像系统漏洞？**这 8 组的四件套一侧，全部需要麦金卡会员身份。** 没卡的人拿不到那个价。所以这个项目**默认按"人人可买的价格"推荐**，会员价要你明确说一句"我有卡"才纳入——每一句结论，都要对没卡的人也成立。

## 为什么不做"让大模型直接推荐"

同一个问题，随便问一个 AI 也能得到一段听起来很专业的回答。区别在于：**那些回答里的商品、价格、营养，多半是编的。**

我的做法是显式约束求解（`scripts/adviser.py`，约 700 行）：

1. **枚举**：在真实菜单上枚举组合（`itertools` 组合展开）
2. **硬约束过滤**：预算、热量区间、蛋白下限、忌口、结构（必须包含主食/小食/饮品）——不达标直接淘汰，不是"尽量避开"
3. **多目标打分 + 帕累托去重**：同一组商品只留真正占优的买法，去掉被支配的方案
4. **输出可解释结果**：每一套方案附：总价、人均营养、推荐理由、券的使用，以及可直接下单的 `order_items`

四种模式的参数是写死的、可测试的：

| 模式 | 热量区间 | 蛋白下限 | 必含结构 |
|---|---|---|---|
| value（最省） | 450–1000 | 15g | 主食 |
| balanced（均衡） | 500–900 | 20g | 主食+小食+饮品 |
| protein（高蛋白） | 600–1200 | 33g | 主食+小食+饮品 |
| light（轻负担） | 330–650 | 17g | 主食+饮品 |

注意价格权重：只有 `value` 模式以压价为主目标（权重 10.0），其余模式**把钱当约束而不是打分目标**——不然算法会退化成"挑最便宜的那个"，而不是"预算内吃得最好"。

忌口也是真剔除：牛肉/猪肉/鸡肉/鱼/辣/咖啡因/乳制品/油炸，各有独立的标签词库（例如"牛堡、巨无霸、吉士、安格斯"→ beef）。说"不要牛肉"，巨无霸就是不出现，没有"尽量"。

## 三种「省」，口径不混着说

同一顿饭能算出三个不同的差额，混着加就是在编数字：

- ✅ **结构省**：同一批商品，换个买法省下的钱（就是上面 ¥12 那笔）。两侧都是真实现价，**确定**。
- ✅ **券后省**：拿券去计价接口实测的抵扣额。**确定**，但以门店核验为准。
- ⚠️ **标价差**：门店"划线价 − 现价"。**单独标注，不与上面相加**——因为你本来也不会按划线价买，拿它当基准吹出来的"省"是假的。

## 券的价值：没有来源就不猜

券的口径优先级是：**实测 > 菜单反查 > 未知**。

- 有券码：把商品码 + `couponId` + `couponCode` 传给官方 `calculate-price`，返回的 `discount`（分）就是精确价值；
- 没券码：从菜单反查原价（买一送一 = 单价；固定价券 = 原价 − 固定价）；
- 两条都走不通：**如实写"价值未知"，绝不填 0、绝不估一个看起来合理的数**。

券的"用不用得上"才是关键——`coupon_doctor.py` 会分析你的真实历史订单（`order-list` 经过本地脱敏）算出点单频率，告诉你哪张先用、哪张注定过期。**假设错了，建议就是错的**：按实测的 0.26 单/周算，浪费 ¥13.2；按"每周 3 单"的拍脑袋假设算，结论会翻成"几乎不浪费"。

# 比赛后的长尾内容草案

目标：把项目从一次比赛投稿变成可长期搜索、复用的 MCP 工程案例。所有价格例子须注明门店与快照日期；实时能力和本地离线演示分开说明。

## 主文章

**标题**：从麦当劳 MCP 到可解释的点餐求解器：价格、营养和优惠券如何落到代码里

**读者**：在做 MCP 工具、消费决策或数据驱动 Agent 的开发者。

**结构**

1. 一个可复现的问题：巨无霸 + 薯条 + 可乐，单点 ¥48.5，三件套 ¥36.5（深圳同方信息港，2026-10-14 快照）。
2. 数据链路：门店选择 → 菜单 → 营养 → 券与计价；说明 Token 的使用边界。
3. 求解方法：菜单建索引、商品身份、价格层级、硬约束、候选排序。
4. 易错点：会员价误当普适价、套餐营养当实测、盲盒商品身份、券价值从名字猜测。
5. 可复现演示：在线快照 Demo、`python demo.py`、测试与真实 MCP 配置路径。
6. 隐私与边界：订单摘要脱敏、价格时效、非官方声明。
7. 结尾：源码、演示、接入指南和 issue 反馈入口。

## 后续短文选题

- **会员价为什么必须单独标**：用三件套 / 四件套例子说明价格口径对预算约束的影响。
- **优惠券面值为什么不能靠券名猜**：展示实测、菜单反查、未知三层价值来源。
- **MCP 返回值到可解释建议**：展示如何让模型负责理解、把金额计算交给确定性程序。

## 发布维护规则

- 每个数字都链接到可复现输出或明确标出数据快照。
- 快照更新后重算文中的数字，不保留已过期的价格作为当前门店承诺。
- 文章结尾保留 Demo、GitHub、MCP 接入文档三个入口。
- 将读者提出的价格 / 商品身份问题整理为 issue，再在版本说明中记录修正。
